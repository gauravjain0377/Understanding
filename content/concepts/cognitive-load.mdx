Every interaction with software requires mental effort. Cognitive load is the amount of mental resources needed to understand and use an interface. High cognitive load makes software feel difficult and tiring, while low cognitive load makes it feel effortless and natural. Understanding cognitive load reveals why simplicity and clarity are more important than features.

Cognitive load theory comes from psychology and describes how working memory has limited capacity. When using software, users must hold information in working memory — what they're trying to do, what the interface shows, what actions are available. If the interface requires too much mental effort, users become overwhelmed and make mistakes.

Understanding cognitive load helps explain why some interfaces feel easy and others feel difficult, and why reducing cognitive load is one of the most important goals in interface design.

## Types of Cognitive Load

Cognitive load comes in three forms:

- **Intrinsic load**: The inherent difficulty of the task itself. Some tasks are simply complex and require mental effort.

- **Extraneous load**: Mental effort caused by poor design — confusing layouts, unclear labels, unnecessary complexity. This is the load that designers can reduce.

- **Germane load**: Mental effort that helps learning and understanding. This is productive load that builds mental models.

Good design minimizes extraneous load while managing intrinsic load and leveraging germane load for learning.

## Reducing Cognitive Load

Many design principles reduce cognitive load:

- **Clarity**: Clear labels, obvious actions, predictable behavior
- **Consistency**: Similar things work similarly, reducing the need to learn new patterns
- **Progressive disclosure**: Show only what's needed, hide complexity until it's relevant
- **Feedback**: Immediate, clear feedback about what's happening
- **Chunking**: Group related information together, making it easier to process
- **Elimination**: Remove unnecessary elements that compete for attention

These principles aren't about dumbing down interfaces — they're about removing unnecessary mental effort so users can focus on their actual goals.

## The Mental Model

Think of cognitive load as the weight of a backpack. A light backpack is easy to carry — you can move freely and focus on where you're going. A heavy backpack is exhausting — you're constantly aware of the weight, and it limits what you can do. Cognitive load works the same way: low load lets users focus on their goals, while high load makes them constantly aware of the interface.

This mental model helps explain why reducing cognitive load is valuable. Just as a lighter backpack makes hiking easier, lower cognitive load makes using software easier. Users can focus on what they're trying to accomplish rather than fighting with the interface.

## Why This Matters

Understanding cognitive load changes how you think about interface design. You begin to see that every element, every label, every interaction adds to the mental effort required. You understand why simplicity is valuable — not because users are stupid, but because mental resources are limited.

You also begin to appreciate that cognitive load is cumulative. A small amount of load from many sources adds up. A confusing label here, an unexpected behavior there, unnecessary information everywhere — these small loads combine to make an interface feel difficult.

More fundamentally, understanding cognitive load reveals that good design is about respecting human limitations. Working memory is limited, attention is limited, mental energy is limited. Good design works within these limitations rather than fighting against them.
